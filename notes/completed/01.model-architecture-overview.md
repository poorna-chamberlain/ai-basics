# 01. Model Architecture Overview: Structural Foundations

Understanding *why* models behave differently starts with architecture.

---

## What is a Language Model Architecture?

All modern LLMs (Claude, GPT, Gemini, Llama) are based on the **Transformer architecture** (Vaswani et al., 2017), but they differ significantly in:

1. **How the architecture is modified** (hidden layers, attention heads, etc.)
2. **How they're trained** (data, objectives, reward modeling)
3. **How they're fine-tuned** (instructions, safety alignment)
4. **Context management** (how they handle long documents)
5. **Multi-step reasoning** (how they break down problems)

---

## The Transformer Core: Same But Different

All models use transformers with these components:

```
Input Text 
    ↓
Tokenization (breaking text into chunks)
    ↓
Embedding Layer (converting tokens to vectors)
    ↓
Attention Mechanism (understanding relationships)
    ↓
Feed-forward Networks (processing information)
    ↓
Output Layer (generating next token)
```

**KEY INSIGHT**: The differences emerge in how these components are weighted, interconnected, and used during training.

**Why it matters for code**: 
- Claude's configuration helps it understand how changes in one file affect others
- GPT's configuration is more general-purpose

## Why Claude is Better for "Project-Aware" Code Generation

### The 1-Prompt vs 3-Prompt Problem

**Claude typically solves in 1 prompt**:
```
User: "Add authentication to this codebase"
Claude: 
  1. Analyzes your entire project structure (via 200K context)
  2. Identifies existing patterns (your auth approach, folder structure, etc.)
  3. Generates code that MATCHES your patterns
  4. Updates all related files in harmony
  5. Returns complete solution
```

**GPT typically needs 3 prompts**:
```
User: "Add authentication to this codebase"
GPT (Prompt 1): Generates basic auth module
  Issue: Doesn't match your project structure

User: "This doesn't match our structure, we use [X pattern]"
GPT (Prompt 2): Regenerates with pattern
  Issue: Doesn't integrate with existing code

User: "Update the existing files to use this new auth"
GPT (Prompt 3): Finally integrates
  Result: Works, but took 3x the tokens
```

### Structural Reason for This Difference

**Claude's training philosophy** (via Constitutional AI):
- Trained to be "helpful, harmless, honest"
- Strong emphasis on **understanding context and implications**
- Penalizes solutions that contradict the existing system
- "Think holistically about the user's entire system"

**GPT's training philosophy** (via RLHF):
- Trained to follow instructions very literally
- Optimized for **task completion** not context harmony
- Can excel at isolated tasks
- "Do exactly what was asked, in the most direct way"

**Analogy**:
- **Claude**: A senior architect who asks "How does this fit into your existing design?"
- **GPT**: A skilled worker who says "Here's how to do this task" (very well)

## Key Architecture Features Explained

### Constitutional AI (Claude's Secret Weapon)

This is trained-in value system:
- Not just "do what user asks"
- But "do what user asks in a way that makes sense in context"
- This makes Claude naturally project-aware

### RLHF (Reinforcement Learning from Human Feedback)

All models use this, but differently:
- **Claude**: Reward signal emphasizes "helping the user achieve their goal" (broader)
- **GPT**: Reward signal emphasizes "following instructions" (narrower)
- **Llama**: Reward signal emphasizes "being helpful" (varies by version)

This seemingly small difference compounds: Claude learns to think about the whole system, GPT learns to do exactly what's asked.

## Implications for Code Generation

### Why Claude Gives Better Code in 1 Shot

1. **Sees more context** (200K window) → understands your project
2. **Trained to understand implications** → thinks about consistency
3. **Constitutional approach** → asks "does this make sense in this project?"
4. **Better long-range dependencies** → understands how files connect

### Why GPT Needs Multiple Turns

1. **Smaller initial context** → might miss your patterns
2. **Task-focused training** → generates correct code, not contextual code
3. **Instruction-literal** → does exactly what asked, even if suboptimal
4. **Shorter training context** → wasn't trained to think in terms of "projects"

### Why Gemini Struggles with Code

1. **Optimized for multimodal** → code is just one data type to it
2. **Broader training** → weaker at code-specific patterns
3. **Different attention patterns** → not tuned for code relationships
4. **Smaller context for pure code** → despite 1M tokens, coding isn't primary focus
