## Detailed Decision Matrix

### 1. Project/Code Task?

**Signs**:
- Adding features
- Refactoring code
- Modifying existing project
- Multi-file changes needed
- Need to match project style

**Decision**:
```
├─ Large feature (architecture affects 5+ files)?
│  └─ Claude 3.5 Sonnet ✅✅✅
│     - Sees full context
│     - Integrates properly
│     - One-shot success
│
├─ Medium change (affects 1-3 files)?
│  └─ Try Claude Haiku first
│     └─ Failed? → Claude Sonnet
│
└─ Small change (affects 1 file)?
   └─ Claude Haiku ✅
      - Cheap
      - Fast
      - Still project-aware
```

**Cost consideration**:
```
Haiku for small:      $0.0008 (try first!)
Sonnet for large:     $0.003 (necessary for integration)
Always-Sonnet:        Wastes 75% of budget
Always-Haiku:         Fails on complex tasks
Balanced approach:    Optimal ✅
```

---

### 2. Algorithm/Technical Problem?

**Signs**:
- "How do I implement X algorithm?"
- "Optimize this function for performance"
- "What's the best approach to solve this?"
- "Explain complex technical concept"

**Decision**:
```
├─ Pure algorithmic (no project context)?
│  └─ GPT-4 Turbo ✅
│     - Deep technical expertise
│     - Optimal solutions
│     - Explains trade-offs
│
├─ Algorithm + project integration?
│  └─ Claude Sonnet ✅
│     - Understands algorithm
│     - Integrates into project
│     - One-shot solution
│
└─ Simple implementation of known algorithm?
   └─ Claude Haiku ✅
      - Good enough for standard algorithms
      - Saves cost
```

**When to escalate to GPT-4**:
- "Prove this algorithm is optimal"
- "What's the time complexity?"
- "How do I handle edge cases?"
- "Deep mathematical analysis"

---

### 3. Research/Information Gathering?

**Signs**:
- "Find latest best practices for X"
- "What are the new frameworks in 2026?"
- "Analyze these 5 papers"
- "Compare different approaches"

**Decision**:
```
├─ Pure research (no coding)?
│  └─ Gemini 1.5 Pro ✅
│     - Can read images/diagrams
│     - Large document support (1M tokens)
│     - Good at synthesis
│
├─ Research + implementation needed?
│  ├─ Gather info with Gemini
│  └─ Implement with Claude
│
└─ Quick "What's the best practice?" (2026)?
   └─ Try Haiku first
      - If insufficient → Gemini
```

**Multi-step approach**:
```
Step 1: Gemini gathers research
Step 2: Claude interprets for your project
Step 3: Implement with Claude
Result: Researched + integrated solution
```

---

### 4. Simple Q&A / Routine Tasks?

**Signs**:
- "What does this error mean?"
- "How do I use this library?"
- "Generate a simple function"
- "Explain concept X"
- "Format this data"

**Decision**:
```
┌──────────────────────────────┐
│  ALWAYS TRY HAIKU FIRST      │
│  Save Sonnet for when        │
│  Haiku can't solve it        │
└──────────────────────────────┘

Success rates:
├─ Simple task: 85% first try ✅
├─ Medium task: 70% first try ⚠️
├─ Complex task: 30% first try ❌ (escalate to Sonnet)
└─ Pattern: If fails, escalate
```

---

### 5. Offline/Local Required?

**Signs**:
- No internet available
- Privacy requirements
- Rapid prototyping loop
- Cost absolutely critical

**Decision**:
```
├─ Quality important?
│  └─ Mistral 7B (best offline option)
│
├─ Speed important?
│  └─ Phi-3 (3.8B, very fast)
│
└─ Privacy critical?
   └─ Llama 2 70B (fully private)

Trade-off:
├─ Mistral: 70% quality, 100% free
├─ Phi: 60% quality, lightning fast
└─ Llama: 50% quality, most stable
```

## Priority Checklist

When choosing a model, check in order:

```
☐ 1. Can I solve this offline? → Use Llama/Mistral
☐ 2. Is this research-heavy? → Use Gemini
☐ 3. Is this pure algorithm? → Use GPT-4
☐ 4. Is this project code? → Use Claude
☐ 5. Is it simple/routine? → Try Haiku first
☐ 6. When in doubt? → Start with Haiku, escalate if needed
```

## The 80/20 Rule for Your Work

```
80% of your tasks:
  Claude Haiku
  - Cost: Minimal
  - Success: High (70-85%)
  - Speed: Excellent

20% of your tasks:
  20% complex code  → Claude Sonnet
  5% specialized    → GPT-4 or Gemini
  5% offline        → Llama

Result: Maximum quality, minimum cost
```
